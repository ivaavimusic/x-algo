## Technical Details

Fixes #252.

**TL;DR:** Ranking inference let candidates attend to each other, so a post's score depended on which other posts shared its request. This restores candidate isolation in both inference kernels.

**Bug:** The inference attention kernels treat any 128-token block containing history as all history and skip per-key masking. With the QUICKSTART layout, users with 127 or 128 history events share a block between history and candidates, so candidates see their neighbours. On H100 the history range is fixed from the config, so this happens on every request, and padded history slots are always attended.

**What was added:** `ranker_attention_v2.py` applies the training kernel's key mask in the inference history loop (keep a key only if it is history or the query's own position). `ranker_attention_fa3.py` masks H100 history steps to the history range and keeps the softmax finite for rows with no visible keys. `recsys_attention.py` passes the H100 kernel per-example ranges from `bounds_from_segment_ids` instead of a fixed config range.

**Validation** Tested locally in Pallas CPU interpret mode (JAX 0.8.1): neighbour swaps no longer change candidate outputs, and inference matches the training kernel at 60, 126, 127 and 128 history events. The H100 changes were not executed and need verification on an H100 before merge.
