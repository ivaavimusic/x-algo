## Technical Details

An explicit finished session should be able to stop recommendation work before another batch is fetched or scored. Inspired by [Vible's exit action](https://www.holyvible.com/) and [Empowerverse's intentional-use vision](https://www.empowerverse.org/), this adds an opt-in `CandidatePipeline::request_result_limit(&query)` hook.

- `None` preserves current behavior and is the default for all existing implementations.
- A positive limit caps returned candidates after filtering and finalization, without expanding `result_size()`.
- `Some(0)` returns an empty result with the hydrated query before sourcing, and skips candidate stages, finalization, and serving side effects. Existing size statistics and pipeline summary emission are retained.

Candidates truncated by a positive cap are included in the non-selected partition. Serving side effects see exactly the final returned selected candidates. The cap is read after both query-hydration stages and cannot be exceeded by a finalizer that adds items.

The integration document covers the outer-serving-pipeline boundary, authenticated explicit session state, visible-item versus candidate counts, cursor/prefetch handling, and atomic cross-request budget reservations. This framework hook does not enable a user setting or implement session accounting. Honoring "done" is independent of treating an explicit inspired exit as positive feedback; ordinary closure/inactivity supplies no such label.

Validation:
- Eight async tests pass, compiling the actual public pipeline execution, stage traits, selector, and summary code.
- Covers unchanged legacy behavior, zero-budget early exit, hydrated budgets, ordered positive truncation, side-effect partitions, post-finalizer caps, oversized limits, and legacy static-zero behavior.
- `cargo test --locked --manifest-path candidate-pipeline/tests/request-budget/Cargo.toml`
- Rust formatting and `git diff --check`.

The harness uses test stand-ins only for unpublished feature-switch/decider/metrics adapters and a pass-through metrics attribute. Production configuration, telemetry, and Home Mixer integration remain unverified. This PR is independent of #227 and #228.
