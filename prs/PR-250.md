## Technical Details

When Python fallback feature extraction fails for one user, the prefetcher skips that feature row but truncates the original UID list to the new batch length. For input users `[11,22,33]` with extraction failure for `22`, it therefore publishes features for `[11,33]` under UIDs `[11,22]`. That can attach the next account's scores to the failed account, and the freeze path also selects the wrong raw sequence.

Retain the successful `(user_id, raw_sequence)` rows alongside extracted batches, and derive the published UID list and freeze input from those same rows.

Validation: the actual prefetcher loop, real Arrow extractor/merger and serializer fail four regression cases before the change; thirteen focused and adjacent tests pass afterward with no skips. The regression covers first/middle/last/no extraction failure with freezing enabled and disabled, checking published IDs, features, score IDs, histogram/summary lengths and frozen UID/raw-sequence alignment. Redis, sequence-store and Kafka boundaries are local fakes, and the extraction failure is injected; no live services or GPU are involved.

Prepared with AI assistance; the patch and regression results were independently reviewed before submission.
