## Technical Details

Addresses #203.

Every sync of `home-mixer/params/param.rs` has the same commit message and also rewrites the `// ... last sync` header. Right now the only way to find out which ranking weights moved is to diff by hand. Of the 48 syncs that touched `param.rs` or `vm-ranker/params.rs`, 11 changed nothing but that header. The others changed values with no description. For example, between b089ce6 and 6bb4594, `VqvWeight` went 0.05 → 0.0, `DwellWeight` went 0.0 → 0.05 and `VideoOpenWeight` went 0.05 → 0.07.

This adds `home-mixer/scripts/param_changelog.py`, which parses each `param!(Name, type, "key", default)` and compares two revisions. Comments, the sync header and reformatting are ignored, so only real value changes show up.

- `diff <old> <new>` prints a Param / Old / New table for any two commits.
- `history --output docs/PARAM_CHANGES.md` rebuilds the full log, one section per sync with a link to the commit. Syncs that only changed the header get a one-line label.

`docs/PARAM_CHANGES.md` is backfilled from first publication (47c1bcd) through 862a123. `vm-ranker/params.rs` is tracked too, because it keeps its own copy of the ranking weights. Each section has a `<!-- note:<sha> -->` block for a plain-language explanation in the style of `BIDIRECTIONAL_BOOST_CHANGE.md`. When a section changes a weight, the block holds a placeholder. Notes are kept when the file is regenerated.

`.github/workflows/param-changelog.yml` runs on pushes to `main` that touch either params file. It runs the tests, writes the sync's table to the job summary, tags the commit `sync-<UTC timestamp>`, regenerates the changelog and opens a PR with the update. A PR is used instead of a direct commit so someone can fill in the note before merging. README links the changelog from "Experiments and Configuration".

Tested with Python 3.12: pytest covers single- and multi-line `param!`, `//` inside string literals, `vec![...]` defaults, reformatting not counting as a change, and note round-tripping. `ruff check` and `ruff format` are clean at the repo's 100-character line length. The parser finds all 191 params in `param.rs` and all 51 in `vm-ranker/params.rs`. Running `diff b089ce6 6bb4594` gives every change listed in #203. Regenerating twice produces identical output. The workflow has not run, since this repo has no Actions yet.

Not included: the plain-language notes themselves. Only xAI knows why a weight changed, so they're left as placeholders. Enabling the workflow requires "Allow GitHub Actions to create and approve pull requests" and uses `peter-evans/create-pull-request`. The tag and PR steps can be dropped if you'd rather keep that in the internal sync. Prepared with AI assistance.
